# ДОСЬЄ 08b: УКРАЇНСЬКИЙ ПОНЯТТЄВИЙ ШАР ПОВЕРХ OPEN-SOURCE МЕХАНІЗМІВ
## Питома семантика відносин замість калькованого легалізму

> **Методологічне правило:** Не калькувати англомовні терміни (`copyleft` ➔ «копілефт», `downstream` ➔ «даунстрім», `grant` ➔ «грант»).  
> Замість пошуку фонетичних відповідників ми:
> 1. Виділяємо **реальне правове відношення**, що відбувається між людьми;
> 2. Знаходимо **питоме українське поняття**, здатне точно його виразити;
> 3. Будуємо міст між нашою мовою та сучасними інженерними кандидатами реалізації (без підміни семантики реалізацією).

---

### 1. ФУНДАМЕНТАЛЬНЕ РОЗРІЗНЕННЯ: ПРАВО VS ВОЛЬНІСТЬ

Сучасний англомовний термін `freedom` у сфері софту є перевантаженим і поєднує різні рівні дійсності. В українській концептуальній системі ми розрізняємо:

```text
       ПРАВО                               ВОЛЬНІСТЬ
(конкретна дозволена дія)       (захищений простір таких дій)
          │                                   │
«Я можу виконувати,                «Цей простір не повинен
 вивчати чи змінювати цей код»      свавільно звужуватися чи зникати
                                    лише тому, що твір передано через
                                    посередника або в руки влади»
```

- **`ПРАВО` (Right / Permission):** Свобода здійснювати позитивні дії щодо твору (запуск, читання, зміна, поширення).
- **`ВОЛЬНІСТЬ` (Libertas / Protected Space of Action):** Нормативний імунітет від свавільного звуження, відчуження або знищення прав; стійкий стан незакріпаченості суб'єкта щодо твору.

---

### 2. СИСТЕМНИЙ СЛОВНИК ВІДНОШЕНЬ: УКРАЇНСЬКЕ ПОНЯТТЯ ↔ СУЧАСНИЙ ОПЕРАТОР

Ми будуємо двосторонній міст, де українські поняття формулюють **семантику**, а сучасні юридичні терміни — **інженерні кандидати реалізації** (знак `?` позначає відсутність прямого відношення 1:1):

| Українське поняття | Що ним реально називаємо у відношенні | Відповідний сучасний open-source механізм | Кандидати сучасної юридичної реалізації (Implementation Candidates) |
| :--- | :--- | :--- | :--- |
| **`ПРАВО`** | Можливість людини вільно здійснювати дії з твором | permission / copyright grant / right to run, copy, modify | Unilateral waiver, non-exclusive copyright license, statutory fair use exception |
| **`ВОЛЬНІСТЬ`** | Захищений простір дій, який не може бути свавільно відібраний | software freedom / non-enclosure | Irrevocable license clause, promissory estoppel, protection against technological locks (anti-DRM) |
| **`ДОГОВІР / ПАКТ`** | Взаємне відношення прав і меж між сторонами твору | license agreement / public contract / terms | Public offer, multilateral covenant, standard terms, unilateral bare license with conditions |
| **`УМОВА / ЗОБОВ'ЯЗАННЯ`** | Межа або дія, необхідна для правомірності використання | condition / affirmative covenant / obligation | Condition precedent, conditional copyright permission, negative covenant |
| **`ПІДТВЕРДЖЕННЯ ПОХОДЖЕННЯ`** | Обов'язок не приховувати джерело та авторів твору | attribution / copyright notice / NOTICE file | Notice preservation requirement, moral rights acknowledgment (paternity right) |
| **`НАСТУПНИЙ НАБУВАЧ (НАСТУПНИК)`** | Суб'єкт, до якого твір переходить далі по графу | downstream recipient / licensee | Third-party beneficiary, direct licensee (FSF model), subsequent possessor |
| **`ЗБЕРЕЖЕННЯ ВОЛЬНОСТЕЙ`** | Неможливість посередника обрізати свободу наступника | pass-through rights / copyleft / viral condition (?) | Direct automatic grant from author (§10 GPLv3), file-level copyleft (§3.1 MPL-2.0), covenant running with asset (?) |
| **`ПОРУШЕННЯ`** | Вихід за межі договору або використання права для утиску інших | breach / infringement / default | Breach of contract, copyright infringement (naked act without license) |
| **`ПОЗБАВЛЕННЯ / ПРИПИНЕННЯ ПРАВА`** | Наслідок порушення: втрата дозволу на користування | termination of license | Automatic termination, termination on notice, judicial rescission |
| **`ПОНОВЛЕННЯ ПРАВА`** | Відновлення дії дозволу після усунення порушення | reinstatement / cure period | 30-day cure period, provisional cure, formal acknowledgment of compliance |

### 3. НОРМАТИВНИЙ ШАР ДОГОВОРУ (PACTA LAYER)

На концептуальному рівні PACTA повністю відмовляється від термінів `open source`, `copyleft`, `covered code`, `downstream`:

```text
                                ДОГОВІР (PACTA)
                                       │
        ┌──────────────────────────────┼──────────────────────────────┐
        │                              │                              │
      ТВІР                       ПРАВА ТА ВОЛЬНОСТІ              ЗОБОВ'ЯЗАННЯ
(інформаційний артефакт,         (свобода дії та               (непозбавлення прав,
 вихідний стан або зміни)         захищений простір)            підтвердження походження)
        │                              │                              │
        └──────────────────────────────┼──────────────────────────────┘
                                       │
                       НАСТУПНИК (НАБУВАЧ У ГРАФІ)
                                       │
                             ПОРУШЕННЯ ТА ПОНОВЛЕННЯ
```

> **Канонічна формула спадкоємності у проєкті PACTA:**  
> *«Наступний набувач не має бути позбавлений тих вольностей щодо переданої частини твору, які були з нею поєднані творцем.»*

### 4. АРХІТЕКТУРНИЙ ВИСНОВОК

1. **Наша мова не залежить від англомовного субстрату:**  
   Ми мислимо категоріями `ПРАВО`, `ВОЛЬНІСТЬ`, `ДОГОВІР`, `ЗОБОВ'ЯЗАННЯ`, `ПОРУШЕННЯ`, `ПІДТВЕРДЖЕННЯ`.
2. **Юрист отримує однозначну функціональну матрицю:**  
   Коли юристу ставиться завдання скласти драфт для суду, він бере не розмите слово «вольність», а конкретний набір пов'язаних операторів (irrevocable permission + no further restrictions + attribution notice).
3. **Ліцензія (License) є зовнішньою оболонкою:**  
   Слово `license` залишається технічним терміном IP-права для судових інстанцій, тоді як сутністю відношення між автором і спільнотою є **Пакт прав і вольностей (PACTA)**.
